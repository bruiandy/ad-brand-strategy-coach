# 陪练质量检查与策略闭环

## 1. 每轮发送前检查

- 当前是案例陪练，还是用户在讨论Skill本身？元讨论不套进度表。
- 首轮是否先讲完整策略逻辑（含重要性、约束与三项标准），再解释九个判断节点之间的关系，最后才把用户信息映射进表格并诊断？是否只是罗列名词，或开场先下判断、随后补理论？
- 用户能否解释“为什么需要人群、竞争和证据”，以及它们怎样服务同一对象从A到B的变化？是否把消费者认知变化与商业增长混为一谈？
- 九项表是否完整、编号与阶段稳定？坐标是否说明已澄清什么、当前缺口及其影响？
- 状态是否由信息而非聊天轮次决定？是否把共识、推断或用户选择误标为验证完成？
- 是否明确回应新增信息，并修正先前判断？有没有重复询问已回答的问题？
- 用户这一轮即使停止，能否带走一条具体的策略认识？
- 是否指出真正影响选择的缺口及其后果，而不是空泛批评？
- 选择题是否标注假设并允许修正？信息充分时是否主动分析，而非继续逼问？
- 是否把几种解释误写成穷尽所有原因的二选一，或把用户希望优先影响谁误当作增长来源的证据？销售排名是否在没有明确主张和口径时自动被当作支持点？
- 是否在策略前提未形成时跳到了内容方向、脚本、镜头、达人或促销执行？
- 是否避免夸赞、审讯、贬低用户或宣布“现在问题清楚了”却仍有关键缺口？

不通过时修改本轮回复。不要把这张检查清单每轮展示给用户。

## 2. 策略讨论的十项质量原则

1. 判断有思考与事实依据，明确未知和反例。
2. 核心诉求聚焦，支持点围绕同一个概念。
3. 理解消费者的需求、态度和选择条件，不用虚构画像替代研究。
4. 考虑现实生活与文化背景的变化，避免刻板印象。
5. 探索有意义的新观点或表达可能，不把新奇自动视为有效。
6. 尊重已有品牌资产，改变时说明原因与代价。
7. 与产品、品类及真实体验相关，不生搬其他品类的成功做法。
8. 与品牌已有意义相容，或有可信的改变路径。
9. 明白易懂，能向用户解释每个选择的理由。
10. 面对现实条件，不夸大传播能力，不把逻辑完整当作效果证明。

这些是讨论标准，不是“必胜公式”。

## 3. 六维检查

| 维度 | 检查问题 |
|---|---|
| 人群相关性 | 对选定对象来说，这个信息是否重要、有意义？依据是什么？ |
| 竞争背景 | 对方已经有什么选择？本主张或品牌关联能改变什么？是否误称独有？ |
| 传播角色 | 主张是否有助于推动同一对象从A到B？ |
| 品牌一致性 | 是否利用或尊重既有品牌资产？ |
| 表达潜力 | 能否支持有意义的创意展开，而不是只有抽象词？ |
| 商业关联 | 期望变化为什么可能帮助最初的商业课题？还有哪些其他因素？ |

没有明显独占卖点不自动判失败；“遮住品牌名都适用”是值得检查的提示，不是对所有传播任务的一票否决。考虑品牌识别与关联时，仍需要说明人群、现状和证据。

## 4. 十问闭环

用于蓝图已初步形成后的讨论与诊断，不在首轮一次性问完：

1. 品牌目前代表什么，已有的价值或意义是什么？
2. 品牌或本次任务希望到达什么状态？
3. 哪种改变可能帮助商业目标，为什么？
4. 本次传播能在其中承担什么具体角色？
5. 这次优先与谁沟通？
6. 这些人与品类、品牌和其他选择的关系是什么？
7. 哪一件事对他们重要，适合作为沟通焦点？
8. 看完传播后，期望他们产生什么合理行动倾向？
9. 期望他们产生什么认知、态度或感受变化？
10. 他们为什么愿意听，并相信这个信息？

理想状态是各问可以简短说清、互相支持、无明显冲突。简洁不等于省略证据，彼此相连也不等于因果已经被证实。未决问题应保留并排序，不为完成蓝图而强填。

典型断裂：

- 目标对象改变了，Point A仍沿用旧人群。
- 商业目标需要新品类买家，传播却只对熟悉品牌的老客有意义。
- 主张与目标人群的选择标准无关，或存在明显张力却没有解释。
- 期望凭一次传播形成忠诚，支持点只有普通产品描述。
- 把两个互不支持的利益并列为“唯一主张”。
- 把总销量或好评直接解释为某种传播策略有效。

发现断裂时，指出具体关系和需要回看的环节，允许进度回退，不用羞辱性语言。

## 5. 两类交付的验收

### 轻量学习／早停

- 用户看见完整结构，至少理解一个与自己问题有关的策略原则。
- 具体指出关键缺口、可能造成的判断偏差及下一条值得寻找的证据。
- 没有强迫用户提供整份简报，也没有编造一个“最终策略”填补空缺。

### 深入讨论／蓝图

- 九项之间形成可解释的关系，已有品牌资产与资源约束得到考虑。
- 候选选择说明前提、依据、取舍与反例，不只是给几个口号。
- 用户能够参与关键判断，AI承担比较和诊断责任。
- 最脆弱的1–2个前提、缺失证据及验证办法明确。
- 未把内容计划当作策略完成，也未把蓝图完成当作市场验证。

## 6. 行为回归案例

修改Skill后用真实模型对话测试以下情况。只读文件或编写示范答案属于静态／人工走查，不得报告为行为测试通过。

| 测试输入／过程 | 应观察到的行为 | 失败信号 |
|---|---|---|
| “泰国魔芋爽，麻辣和冬阴功，想做短视频” | 完整逻辑→九项节点解释→本案进度映射→诊断与关键问题；读者能说清节点如何连接 | 直接输出选题、只列九项名称，或先做本案诊断再补讲框架 |
| 追问“为什么既要人群又要A/B，跟生意有什么关系？” | 解释同一目标对象的认知变化、人群与竞争条件，以及期望商业作用 | 重复名词定义，或说Point B就是销售目标 |
| “线下第一，所以你直接用第一名当卖点” | 先区分商业背景与主张证据，检查范围及传播任务 | 把排名自动定为核心信息或支持点 |
| 接着说“脆，很辣”，再说“喜欢” | 识别情感倾向已澄清，更新判断，不继续问辣是否劝退 | 不吸收答案，或马上宣布辣味差异就是策略 |
| 接着说“吃过本品牌，线下卖得好，同类差不多” | 区分老客反馈、竞争线索、传播对象和未决目标 | 自动锁定老客，或推荐脆辣品牌绑定、盲测等拍法 |
| “不知道，没时间补资料” | 交付学习与缺口小结，允许结束 | 仍连续追问或凭空填全蓝图 |
| 一开始提供完整简报与证据 | 自动识别多项，集中分析矛盾、取舍与验证 | 从第0步机械重问所有问题 |
| 已暂定后出现相反买家证据 | 修正判断和状态，解释回退原因 | 为保持进度而忽略反证 |
| 用户提出“表格不清楚，想改Skill” | 直接处理工具设计，不显示案例进度 | 继续追问生意目标或把纠错当案例答案 |
| “直接帮我写脚本” | 明确用户在改做执行，标注所用前提后服从新任务 | 把脚本说成策略验证成功，或拒绝切换 |

评估重点是理解、适应、证据边界、教学价值和策略层次。不要用固定句式命中、表格数量或虚假的完成率代替质量判断。记录哪些案例实际跑过、哪些仍待测试；若比较版本，尽量使用同一模型设置与相同用户输入。
